# 피치 비디오 대본 & 화면 구성

## 목표/톤
- 목표: RWA 거래 활성화 문제를 제시하고, 단일 코어 풀 + Virtual Reserve + Reservation으로 해결한다는 점을 빠르게 전달
- 톤: 명확하고 간결, 기술적 신뢰 강조
- 길이: 1분 30초 ~ 2분

## 전체 구성 (타임라인 + 대본 + 화면)

### 0:00 - 0:10 오프닝 (Hook)
**대본**
“RWA를 온체인에 올리는 것만으로는 거래가 생기지 않습니다.  
우리는 RWA 거래량을 실제로 늘리는 구조를 만들었습니다.”

**보여줄 것**
- 프로젝트 타이틀/로고
- 한 줄 비전: “One core pool, many markets”

### 0:10 - 0:30 문제 정의
**대본**
“기존 AMM은 깊은 유동성과 높은 변동성을 전제로 합니다.  
하지만 RWA는 공급이 제한되고 가격 안정이 핵심이라, 기존 AMM 구조에서는 슬리피지와 가격 왜곡이 커집니다.  
결국 발행자는 유동성 제공을 꺼리고, 사용자는 거래를 회피합니다.”

**보여줄 것**
- “RWA vs AMM” 비교 그래프 (슬리피지 급증)
- “낮은 거래량/낮은 유동성” 악순환 다이어그램

### 0:30 - 0:55 솔루션 개요
**대본**
“해결책은 풀을 늘리는 것이 아니라, 하나의 RWA 유동성을 모든 경로에 안전하게 공유하는 것입니다.  
우리는 단일 Core Pool, Derived Spot Pools, 그리고 Liquidity Hub Router를 결합했습니다.”

**보여줄 것**
- 아키텍처 다이어그램 (Core Pool → Derived Pools → Router)
- 키워드 강조: “Single Core Pool”, “Derived Pools”, “Router”

### 0:55 - 1:15 가격 형성과 안전장치
**대본**
“가격은 오라클 없이 Virtual Reserve AMM으로 형성됩니다.  
실제 체결은 항상 실물 재고 한도 내에서만 이루어집니다.  
재고를 초과한 수요는 Reservation으로 전환되어, 취소하거나 나중에 클레임할 수 있습니다.”

**보여줄 것**
- “Real vs Virtual Reserves” 개념 그림
- Reservation Queue UI/리스트
- “Not a token, not transferable, cancellable” 캡션

### 1:15 - 1:35 참여 방식 (기관/개인)
**대본**
“기관은 초기 유동성을 제공하며, 가격 변동폭을 사전에 설정할 수 있습니다.  
개인과 LP는 이후 누구나 유동성에 참여하고, 다양한 파생 페어에서 RWA를 거래할 수 있습니다.”

**보여줄 것**
- 기관 설정 화면: `maxPriceMoveBps` (예: ±30% 기본, 변경 가능)
- LP 추가/제거 화면
- 파생 페어 예시 (RWA/ETH, RWA/USDC)

### 1:35 - 1:55 데모 플로우
**대본**
“데모에서는 스왑 → 재고 캡 → 예약 생성 → 유동성 추가 → 예약 클레임까지 이어집니다.”

**보여줄 것**
- 실제 UI 시퀀스
  1) Quote 화면 (cap 여부 표시)
  2) Swap 실행 → 예약 생성
  3) Add Liquidity
  4) Process Queue / Claim

### 1:55 - 2:00 마무리
**대본**
“우리는 RWA를 위한 또 하나의 풀을 만들지 않습니다.  
하나의 RWA 유동성으로, 탈중앙 DEX 전체의 거래를 확장합니다.”

**보여줄 것**
- 비전 문구 풀스크린
- GitHub 링크/팀명

## 촬영 체크리스트
- UI/데모 화면은 사전에 주소/토큰/수량을 고정해 재촬영 리스크를 줄이기
- Reservation 생성/클레임 시 로그 또는 토스트 강조
- “Oracle 없음”과 “실재고 캡”은 반드시 시각적 콜아웃으로 강조
- 가격 변동폭 설정은 “선택 사항(Pre-init)”임을 명시

## 보너스: Q&A에서 강조할 포인트
- 오라클 없이 가격 형성 → 가격 책임/조작 리스크 최소화
- Reservation은 자산이 아니라 **대기 상태**이며 언제든 취소 가능
- 발행자/기관은 가격 제한폭을 설계해 시장 급등락 리스크를 제어 가능
