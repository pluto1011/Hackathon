# 피치 비디오 대본 & 화면 구성

## 프로젝트 소개 문구
“RWA Liquidity Hub는 단일 RWA/Stable 코어 풀과 Virtual Reserve AMM으로 RWA 거래를 활성화하는 인프라입니다.”

## 목표/톤
- 목표: RWA 거래 활성화 문제를 제시하고, 단일 코어 풀 + Virtual Reserve + Reservation으로 해결한다는 점을 빠르게 전달
- 톤: 명확하고 간결, 기술적 신뢰 강조
- 길이: 1분 30초 ~ 2분

## 전체 구성 (타임라인 + 대본 + 화면)

### 0:00 - 0:10 오프닝 (Hook)
**대본**
“지금 보시는 프로젝트는 RWA를 온체인에 올리는 것에서 멈추지 않습니다.  
RWA 거래량이 실제로 늘어나는 구조를 보여드리겠습니다.”

**보여줄 것**
- 프로젝트 타이틀/로고
- 한 줄 비전: “One core pool, many markets”

### 0:10 - 0:30 문제 정의
**대본**
“먼저 문제를 짚어보겠습니다.  
기존 AMM은 깊은 유동성과 높은 변동성을 전제로 설계되었습니다.  
하지만 RWA는 공급이 제한되고 가격 안정이 핵심이기 때문에, 같은 구조를 적용하면 슬리피지와 가격 왜곡이 커집니다.  
그 결과 발행자는 유동성 제공을 꺼리고, 사용자는 거래를 회피하는 악순환이 생깁니다.  
또한 중국·한국·일본·대만처럼 일일 상·하한이 있는 시장이나, 미국·EU·홍콩·싱가포르처럼 가격 밴드/서킷 제도가 있는 시장에서는  
이런 제한 조건을 온체인에서 강제하기 어렵기 때문에 RWA 도입이 더딥니다.”

**보여줄 것**
- “RWA vs AMM” 비교 그래프 (슬리피지 급증)
- “낮은 거래량/낮은 유동성” 악순환 다이어그램

### 0:30 - 0:55 솔루션 개요
**대본**
“해결책은 풀을 많이 만드는 것이 아니라, 하나의 RWA 유동성을 다양한 경로에 안전하게 공유하는 것입니다.  
이를 위해 단일 Core Pool, Derived Spot Pools, 그리고 Liquidity Hub Router를 결합했습니다.  
가격곡선은 단순 x*y=k가 아니라 (x+vRwa)*(y+vStable)=k로 작동해 급격한 가격변동을 완화합니다.”

**보여줄 것**
- 아키텍처 다이어그램 (Core Pool → Derived Pools → Router)
- 키워드 강조: “Single Core Pool”, “Derived Pools”, “Router”

### 0:55 - 1:15 가격 형성과 안전장치
**대본**
“가격은 오라클 없이 Virtual Reserve AMM으로 형성됩니다.  
중앙화된 마켓메이커에 의존하지 않기 때문에 시장조작 위험이 낮습니다.  
하지만 실제 체결은 항상 실물 재고 한도 내에서만 이뤄집니다.  
재고를 초과한 수요는 Reservation으로 전환되고, 사용자는 이를 취소하거나 나중에 클레임할 수 있습니다.”

**보여줄 것**
- “Real vs Virtual Reserves” 개념 그림
- Reservation Queue UI/리스트
- “Not a token, not transferable, cancellable” 캡션

### 1:15 - 1:35 참여 방식 (기관/개인)
**대본**
“참여 방식도 구분됩니다.  
풀 생성 시 가격곡선은 (x+vRwa)*(y+vStable)=k의 가상 리저브 구조를 사용합니다.  
기관은 초기 유동성을 제공하면서, 가격 변동폭을 사전에 설정하거나 기본값을 사용할 수 있습니다.  
개인과 LP는 이후 누구나 유동성에 참여할 수 있고, 다양한 파생 페어에서 RWA를 거래할 수 있습니다.”

**보여줄 것**
- 기관 설정 화면: `maxPriceMoveBps` (예: ±30% 기본, 변경 가능)
- LP 추가/제거 화면
- 파생 페어 예시 (RWA/ETH, RWA/USDC)

### 1:35 - 1:55 데모 플로우
**대본**
“지금 화면에서 먼저 `quote`로 예상 체결량과 캡 여부를 확인합니다.  
이어서 `swap`을 실행하면, 부족한 부분이 예약으로 전환되는 걸 보여드릴게요.  
다음으로 유동성을 추가하고 `processQueue`를 눌러 예약이 체결되는 과정을 확인합니다.  
마지막으로 `claim`까지 진행해 전체 흐름이 끝나는 장면을 보여드립니다.”

**보여줄 것**
- 실제 UI 시퀀스
  1) Quote 화면 (cap 여부 표시)
  2) Swap 실행 → 예약 생성
  3) Add Liquidity
  4) Process Queue / Claim

### 1:55 - 2:00 마무리
**대본**
“정리하면, 우리는 RWA를 위한 또 하나의 풀을 만드는 것이 아니라  
하나의 RWA 유동성으로 탈중앙 DEX 전체의 거래를 확장하는 구조를 제안합니다.”

**보여줄 것**
- 비전 문구 풀스크린
- GitHub 링크/팀명

## 촬영 체크리스트
- UI/데모 화면은 사전에 주소/토큰/수량을 고정해 재촬영 리스크를 줄이기
- Reservation 생성/클레임 시 로그 또는 토스트 강조
- “Oracle 없음”과 “실재고 캡”은 반드시 시각적 콜아웃으로 강조
- 가격 변동폭 설정은 “선택 사항(Pre-init)”임을 명시

## 보너스: Q&A에서 강조할 포인트
- 오라클 없이 가격 형성 → 가격 책임/조작 리스크 최소화
- 중앙화된 마켓메이커 없이 동작 → 시장조작 위험 감소
- Reservation은 자산이 아니라 **대기 상태**이며 언제든 취소 가능
- 발행자/기관은 가격 제한폭을 설계해 시장 급등락 리스크를 제어 가능
